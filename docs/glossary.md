# Glossary

The canonical vocabulary for the coding agent. When code, docs, specs, or conversation use a domain concept, use the term as it appears here. PRs that introduce or rename a domain concept update this file in the same change. Rationale and mechanics live in the referenced ADRs, not here.

| Term | Definition | Notes |
|---|---|---|
| **Harness** | The runtime wrapper around the agent loop: message queue, priority gate, and the wiring to TUI, sandbox, hooks, and services. | The whole running system minus the model itself. |
| **Agent Loop** | The Pydantic-AI ReAct loop that alternates between the LLM and tool calls until the task is done. | One loop per turn. |
| **Priority Gate** | The check between loop iterations that injects newly-arrived user messages into the running loop. | Realised by the Steering + Follow-up queues. |
| **Steering** | A mid-turn user line injected before the next model-request leg (never mid-stream/mid-tool). | Plain `Enter` while busy (ADR-0002 §4). Contrast Follow-up. |
| **Follow-up** | A queued user line drained only when the turn would otherwise stop, continuing as one more turn-leg. | `Alt+Enter` while busy. Contrast Steering. |
| **Decision Channel** | The single mid-turn input surface: a requester awaits a future and the input loop routes the next typed line into it. | Single-flight; serves Deferred Approval and AskUser (ADR-0002 §3-4). |
| **Deferred Approval** | The ask-on-every-tool permission step: a gated tool pauses the run until the human's allow/deny resolves it. | The deferred-tool mechanism that also enables mid-turn steering (ADR-0002 §2-3). |
| **AskUser** | The one blocking, ungated tool: the agent asks a free-form question and the typed answer becomes the tool result. | Rides the Decision Channel, not the gate (ADR-0002 §7). |
| **Sandbox** | The execution boundary for model-chosen side effects: ONE `SandboxExecutor` over a **Sandbox Backend** (`docker`/`modal`) sharing a session-persistent **Workspace**, fresh-exec per call; `none` = host `LocalExecutor`, byte-identical. | The one deliberate infrastructure abstraction (ADR-0011 §1, ADR-0012). Docker contains *accidental* misbehavior; Modal is the untrusted-code rung. |
| **Services Interface** | The boundary exposing LLM Gateway, Memory, LSP servers, and MCP servers to the agent. | Distinct from `tools/` (what the model calls). |
| **Compaction** | The window-relative, cheapest-first cascade that shrinks a long conversation: **Microcompaction** at ~60% full, **full Compaction** (one LLM call, summary + verbatim tail) at ~80% or manual `/compact`. | Full compaction persists as a `compaction` JSONL checkpoint line; replay reconstructs it. `compaction_enabled` gates only the automatic cascade (ADR-0006). |
| **Compaction Boundary** | A valid cut point for the kept verbatim tail: a user-turn `ModelRequest` OR any `ModelResponse` — never a `ModelRequest` carrying a tool return/retry, so a compaction never orphans a tool-call/result pair. | Snap-back goes to the NEAREST valid boundary, not the turn start — one long agentic turn stays compactable. Shared by full Compaction and Microcompaction (ADR-0006 §5 as amended by ADR-0018 §1). |
| **Compaction Outcome** | The three-valued result of a full compaction — `COMPACTED` / `NOTHING_TO_COMPACT` / `SUMMARIZER_FAILED` — surfaced as distinct `/compact` lines and one INFO log line on a fired-but-unsuccessful auto trigger. | Replaces the ambiguous bool; `SUMMARIZER_FAILED` names `.decode/logs/decode.log` (ADR-0018 §3). |
| **Microcompaction** | The cheap, no-LLM, in-memory tier: blanks old tool-output bodies with a placeholder, never removing messages. | Not persisted — resume replays full history and re-microcompacts (ADR-0006 §3a). |
| **Memory Compression** | On-exit compression of `MEMORY.md` at its 200-line cap: one cheap LLM call dedupes/merges instead of drop-oldest (which remains the fallback). | Gated by `memory_compression_enabled`; non-fatal (ADR-0006 §8). |
| **Context Gauge** | The TUI footer fill indicator (`○ ◔ ◑ ◕ ●` + %) showing input tokens vs the compaction window, colored by the same tier thresholds. | Same window setting as Compaction — single source of truth (ADR-0006 §9). Reads the LAST model response's provider-reported request usage (`input_tokens + cache_read_tokens`), never the leg-cumulative sum; immediately after a full compaction it briefly shows the chars≈/4 estimate of the kept history until the next leg reports (ADR-0018 §2, §4). |
| **Subagent** | A child agent spawned via the **Agent tool** for a scoped, read-only task, returning one compressed report — an in-process nested `agent.run()` with narrowed deps. | One ships: **explore** (`subagent: true`). Read-only by construction; spawned via a **Fan-out**; transcripts are ephemeral (ADR-0013, ADR-0017). |
| **Fan-out** | ONE `agent(prompts=[…])` tool call spawning N Explore Subagents concurrently — harness-guaranteed (`asyncio.gather` under the per-loop semaphore) — and folding ONE labelled aggregate back, one section per prompt. | Width-capped at 6 prompts (`ModelRetry`: consolidate); `subagent_max_parallel` is the separate CONCURRENCY ceiling. A single child is a one-element list (ADR-0017 §1-2,4-5). |
| **Subagent Report** | The tight structured summary an Explore child returns: the finding, the file:line evidence, and the trace it followed — compressed so N sibling reports share the parent's fold budget (`subagent_result_max_bytes // N` each). | BAD = empty, or zero tool calls (answered from memory); one retried spawn with a nudge, then an explicit failure note (ADR-0017 §6-8). |
| **Verbose Mode** | The TUI's Ctrl+O toggle (off by default): show each Explore Subagent's tool calls as indented `[child N]` lines in the parent's output, N = its 1-based prompt index. | Live mid-turn — the flag rides `AgentDeps.verbose` and is read at EMIT time, so a running Fan-out obeys it immediately; state shown in the footer (ADR-0013 §8 amendment). |
| **Synthesis Footer** | The harness-appended closing instruction on every aggregated `agent` result: compile the N Subagent Reports into ONE answer — prose plus a text diagram (ASCII default; Mermaid only for genuine graphs). | Just-in-time and in one place — never in persona prompts; appended post-truncation, so it costs no child budget (ADR-0017 §9). |
| **Skill** | A reusable instruction unit: a directory `<name>/SKILL.md` (frontmatter + Markdown body), loaded on demand by the model (`skill(name)`) or the user (`/<name>`). | Injected instructions, not executable code; described actions still pass their own tool gates (ADR-0004 §7). A project skill overrides a built-in of the same `name`. |
| **SKILL.md** | The single canonical entry file of a Skill directory: YAML frontmatter (`name` + `description`) + the instruction body. | The skill's identity is the frontmatter `name`, not the directory name (ADR-0004 §3). |
| **Bundled Resources** | Optional sibling files/folders (`references/`, `examples/`, `scripts/`, …) of a **project** skill, loaded on demand (tier 3). | Project-skill only — built-ins are SKILL.md-only. Surfaced by the dispatcher's resource trailer (ADR-0004 §3). |
| **Skills Catalog** | The lightweight index (name + one-line description per skill) injected into the system prompt. | The "menu"; full bodies load on demand (ADR-0004). |
| **Skill Dispatcher** | The ungated `skill(name)` tool returning a skill's full body (plus a resource trailer when Bundled Resources exist, plus the standing **Outputs Directory** trailer). | Shares `format_skill_payload` with the `/<name>` TUI command; unknown name → `ModelRetry` (ADR-0004 §7). |
| **Progressive Disclosure** | The three-tier skill-loading strategy: catalog always present → body on invocation → resources on demand. | Each tier is paid for only when reached (ADR-0004). |
| **Outputs Directory** | `.decode/outputs/` — the default home for NEW files a skill produces, appended to every skill payload as a standing trailer; a user-named destination always wins. | Gitignored with the rest of `.decode/*` (only `skills/` is tracked), so skill runs never litter the project tree. Edits to existing files stay in place. |
| **Permission Mode** | The gate's evaluation mode — `default` / `plan` / `edit` / `bypass` — deciding allow/ask/deny together with Tool Kind and Permission Rules. | Mutable on the gate; cycled by Shift+Tab (ADR-0003 §1). |
| **Default Mode** | Read-only tools auto-allow; mutating tools ask. | The startup default. |
| **Plan Mode** | Read-only tools auto-allow; every mutating tool is denied with a pointer to `exit_plan_mode`. | ADR-0003 §1,8. |
| **Edit Mode** | Read-only and file-edit tools auto-allow; other mutating tools (`bash`) ask. | a.k.a. acceptEdits; `exit_plan_mode` lands here on approval. |
| **Bypass Mode** | Every tool call is allowed with no prompt. | Use with care. |
| **Tool Kind** | A tool's permission classification — `read_only`, `file_edit`, or `other` — declared once on its registry spec. | `todo_write` is `read_only` (in-memory) — ADR-0003 §2. |
| **Permission Rule** | An allow/deny entry `Tool(pattern)` matched against the call's subject (bash→command, file→path, web→url). | Sources: `.decode/settings.json` + agent frontmatter. Precedence: deny → allow → mode (ADR-0003 §3-4). |
| **Agents Catalog** | The set of built-in agent personas (Build, Plan, Explore, Code-Reviewer): Markdown files with frontmatter + a system-prompt body, validated at startup. | The `subagent: bool` axis splits primaries (`--agent` / `/agent`) from subagent-only personas (explore) — ADR-0003 §5, ADR-0013. |
| **Agent (persona)** | One Agents Catalog entry: an `AgentDef` carrying the system prompt, tool allowlist, optional rules, and default Permission Mode. | Distinct from the Pydantic-AI `Agent` object (ADR-0003 §5-7). |
| **Agent tool** | The model-callable `agent(prompts)` tool that spawns a **Fan-out** of Explore Subagents and returns one labelled aggregate of their **Subagent Reports** plus the **Synthesis Footer**. | `ToolKind.READ_ONLY` — auto-allows. Input guarded (`ModelRetry`) for substance and width; concurrency capped by `subagent_max_parallel`, each child by `subagent_max_requests`. Granted to primaries, never to explore (ADR-0013 §7,10; ADR-0017). |
| **EnterPlanMode / ExitPlanMode** | Model-callable tools switching the gate into Plan Mode and back; `exit_plan_mode` asks the human to approve the plan. | Ungated — they ride the Decision Channel (ADR-0003 §8). |
| **LLM Provider** | The config-selected inference backend — `gemini` / `openrouter` / `modal` — each with its own credentials and default model id. | Default `gemini` keeps existing `.env` files working (ADR-0005 §1). |
| **Provider Seam** | The `agent/factory._build_model()` helper that branches on the LLM Provider; the rest of `build_agent()` stays provider-agnostic. | Gemini → `GoogleModel`; OpenRouter/Modal → `OpenAIChatModel` (ADR-0005 §3, 02_modal_endpoints.md §6). |
| **Code Intelligence** | Semantic understanding of source code — definition, references, hover, diagnostics — via a Language Server, on two channels: the `lsp` tool (active) and the Diagnostics Enricher (passive). | Python-only; best-effort (ADR-0007). |
| **Language Server** | The external LSP process decode shells out to — `ty server` by default, swappable via `lsp_server_command`/`lsp_server_args`. | One per project root, lazily spawned; pull diagnostics only (ADR-0007). |
| **LSP Service** | decode's hand-rolled JSON-RPC-over-stdio client for one Language Server — the first concrete Services Interface entry. | Lazy, cached, best-effort everywhere; no protocol library (ADR-0007). |
| **Diagnostics Enricher** | The passive channel: after a successful `.py` `write`/`edit`, an errors-only diagnostics block is appended to the tool result. | Rides the edit's approval; silent on clean files; gated by `lsp_diagnostics_on_edit` (ADR-0007). |
| **Headless Runtime** | The non-interactive entry path: `decode run "<task>"` drives the same `build_agent()` to completion via a plain `asyncio.run` — bypass permissions, `ask_user` no-op, answer on stdout. | No durability, no pause: a crash is a re-run. Gated by `runtime_enabled`; optionally recorded via the Recording Seam (ADR-0019). `--max-requests N` / `RUNTIME_MAX_REQUESTS` is its one REPL-less knob: a request ceiling for runs nobody watches — past it, one friendly line, exit 1, Hand-back still runs (ADR-0020 Amendment §9). |
| **Recording Seam** | The one decode function that wraps a built agent in `kitaru_pydantic_ai.KitaruAgent` when recording is configured — `KITARU_AGENT_ID` + adapter env present, or a Worker Task's `KITARU_TASK_ID` alone (the adapter infers the agent from the task) — else returns it bare. | User-launched: degrades gracefully to the bare agent with ONE warning when the server is unreachable. Worker-spawned (`KITARU_TASK_ID` set): hard-fails instead. The only kitaru import site outside the bucket seam (ADR-0019 Amendments §3). |
| **Kitaru Session** | One recorded agent run on the Kitaru server: every LLM call and tool call as nodes. The adapter opens one per `run()` call; decode's REPL groups turns via `session_name` = the decode session id. | The unit that Replays, Cohorts, and investigations operate on. Distinct from the decode session (JSONL log) it mirrors (ADR-0019). |
| **Kitaru Worker** | The operator-run process (`kitaru worker start`) that claims Worker Tasks and executes replays in YOUR environment — nothing executes on the server. | NOT the sandbox **Worker** (the Docker/Modal process holding the Workspace) — same word upstream, two concepts here; always qualify as "Kitaru Worker" (ADR-0019). Runs on the laptop (agent v2, docker) or Modal-hosted (`scripts/modal_kitaru_worker.py`, agent v3, none) — same claim loop either way (ADR-0020 §3). |
| **Worker Task** | One unit a Kitaru Worker executes: it spawns the Agent Version's command with `KITARU_TASK_ID` (+ `KITARU_TASK_INPUTS`) in the env; `decode run` reads its task from there when the CLI arg is absent. | Input contract: canonical `{"task": "<prompt>", "model": <id|null>}` wins; the two recorded shapes — a bare `"<prompt>"` string (the adapter's own recording) and `{"input": "<prompt>"}` (the Opik importer's) — are each read as the prompt verbatim; anything else hard-fails, so a replay never guesses its prompt (ADR-0019 Amendments §1). `KITARU_REPLAY_ID` is adapter-native — decode never touches it. |
| **Agent Version** | An immutable registered run spec (command + env + attached secrets + input schema) telling a Kitaru Worker how to execute decode. Version 2 replicates decode's context: `decode run`, `SANDBOX_MODE=docker`, repo-clone Workspace. | A code change = a new agent version; replays target a version (ADR-0019). Version 3 is the Modal-hosted Worker's spec: same command, `SANDBOX_MODE=none` (the gVisor container is the isolation), no `SANDBOX_REPO` (ADR-0020 §5). |
| **Modal Headless App** | The deployed Modal App `decode-headless` (`scripts/modal_headless.py`): its Function runs `decode run "<task>"` in a gVisor-isolated container — synchronously via `modal run`, fire-and-forget (incl. N parallel attempts) via `modal deploy` + the `attempts` spawn helper, on a schedule (`nightly`, a `modal.Cron` configured from `DECODE_NIGHTLY_*` at deploy) or on an event (`webhook`, a proxy-authenticated POST endpoint that spawns a run). | Sandbox Modes `none`/`modal` only — `docker` is guard-rejected (no daemon on Modal). Config = the `decode-headless` Modal Secret + `DECODE_ENV=local`; recording rides the Recording Seam with user-launched (degrade) semantics (ADR-0020, Amendment §8). |
| **Cohort** | A frozen, versioned set of Kitaru Sessions used as a replay/eval population (e.g. `decode-bad-request-400@1`). | Immutable once created; the replay target of the feature's acceptance gate (ADR-0019). |
| **Replay** | Re-executing a recorded Kitaru Session from the top on a Kitaru Worker, optionally with overrides (model / system prompt / prompt / model params) and tool policies. | From-the-top only — no checkpoint anchors, no mid-run forks. `kitaru replay create <session-id>` (ADR-0019). |
| **Baseline Replay** | A no-override Replay of a recorded session — the control proving the run reproduces on the current Agent Version before any what-if change is attributed. | Successor of the retired "Baseline Rerun"; the middle of observed / baseline / forked (ADR-0019). |
| **Environment Bucket** | The named Kitaru secret `decode-<env>` on the managed workspace that hydrates the whole `Settings` surface at a remote `DECODE_ENV` — an exact mirror of `.env`, written only by `make sync-secrets ENV=<env>`. | Semantics unchanged from ADR-0015; transport is the kitaru 0.22.2 client API (ADR-0019). Values land in `Settings` only — never `os.environ`; precedence process env > bucket > defaults, with `.env` dropped entirely at a remote env. |
| **DECODE_ENV** | The bootstrap environment selector — `local` / `dev` / `staging` / `prod` — deciding which injection mechanism feeds `Settings`: `.env` at `local`, the Environment Bucket otherwise. Nothing else. | Resolved out-of-band (dotenv file, overlaid by process env) because it decides whether the bucket is read at all. At `local` (the default) decode never imports kitaru (ADR-0015). |
| **Sandbox Mode** | The `SANDBOX_MODE` setting — `none` / `docker` / `modal` — selecting the backend for the whole process, chosen once at startup. | The startup guard exits friendly if the backend is unavailable or `--repo` is set under `none` (ADR-0011 §1, ADR-0012). |
| **Worker** | The sandboxed process running model-chosen commands and file ops — the Docker container or Modal sandbox hosting the Workspace. | Principle: it holds **exactly** the credentials the user opts into handing it — today `SANDBOX_GIT_TOKEN`, direct-injected as `GITHUB_TOKEN` in **both** backends, and nothing else. A sandboxed process **can read** that token: use a scoped, revocable PAT. Unset → no credential at all (ADR-0016 §2). |
| **Workspace** | The isolated tree a sandbox mode gives the agent: `/workspace` ≡ the host `.decode/sandbox/` ≡ a clone of `--repo`/`SANDBOX_REPO` (or an empty scratch). The agent's whole tool scope (`deps.cwd`) lives here. | Distinct from **Harness Home**. See **Hand-back** (ADR-0012). |
| **Harness Home** | The launch cwd, where all harness artifacts anchor (sessions, MEMORY.md, logs, skills, the permission file), regardless of sandbox mode. Carried on `AgentDeps.harness_home`. | Only the tool scope moves into the Workspace; in `none` mode Harness Home == `deps.cwd` (ADR-0012). |
| **Sandbox Backend** | The thin per-backend adapter (`SandboxBackend` Protocol) behind the one `SandboxExecutor`: exec + file ops + lifecycle. Two ship: `DockerBackend`, `ModalBackend`. | Shared host-side tool logic stays above the seam; only byte transport is per-backend. `none` has no backend (ADR-0012). |
| **Hand-back** | The guarantee that a sandbox session's results survive: a `decode/<session-id>` Session Branch captures the final Workspace (model commits preserved) and is pushed back to the repo's origin, all host-side. | Needs **no** credential in the sandbox — every git command runs host-side with ambient host git creds, whether or not `SANDBOX_GIT_TOKEN` is set (ADR-0016 §4). Triggered on exit, `/ship`, and headless `decode run --repo`; skipped for no-repo / unchanged Workspaces (ADR-0012 §8). |
| **Model Override** | The optional model id (`decode run --model`, or `model` in a Worker Task's inputs) overriding only the active provider's model id for that run. | Never changes the provider. Replay-time model swaps use Kitaru's own replay overrides, not this (ADR-0019). |
| **Trace** | One Opik trace = one REPL turn or one `decode run`: a root span wrapping every LLM and tool call with inputs/outputs, latency, tokens, cost. | Presence-based on `OPIK_API_KEY`; unset → byte-identical no-op (ADR-0014). |
| **Span** | One node inside a Trace — an LLM request, a tool call, or the wrapping turn root — carrying `gen_ai.usage.*` tokens on LLM spans. | The agent-run span uses `gen_ai.aggregated_usage.*` so Opik never double-counts (ADR-0014). |
| **Thread (Opik)** | Opik's conversation-grouping key: the decode session id — the REPL's, or the fresh per-run id `decode run` mints (the same id that names the Kitaru Session and the Hand-back Session Branch). | Purely an Opik UI grouping — not an OS thread (ADR-0014; id source per ADR-0019 §1). |
| **Observability (Opik tracing)** | decode's tracing surface: one `init_tracing()` that, when `OPIK_API_KEY` is present, wires logfire + `instrument_pydantic_ai()` + an OTLP exporter to Opik. | Covers every pydantic-ai agent at once. Distinct from the JSONL session log and from Kitaru Session recording via the Recording Seam (ADR-0014; ADR-0019 keeps them separate by design). |
| **Eval Harness** | The top-level `evals/` package (never shipped in the wheel) that drives decode in-process through Opik `evaluate()` — driver, metrics, judges, datasets, runners. | Distinct from Observability (which traces live use); eval runs log under `EVAL_PROJECT_NAME` (ADR-0017). |
| **Demo Skill** | A showcase Skill (`.decode/skills/demo-N-<slug>/`) whose body walks the agent through one impressive end-to-end scenario, judged by a human — no Opik. | Track A of the eval suite; same Skill contract as ADR-0004 (ADR-0017 §2). |
| **Benchmark Task** | One outcome-oracle task folder (`evals/benchmark/tasks/<NNN>-<slug>/`): `task.yaml` prompt + `setup/` seed + hidden `verify/` oracle + `solution/` gold answer. | The agent never sees `verify/` or `solution/`; Terminal-Bench triad in miniature (ADR-0017 §2,5). |
| **Verify Oracle** | The hidden `verify.sh` (+ optional hidden tests) injected into the Workspace only at grade time; exit 0 = PASS. It IS the grading logic — transparent by design. | Proven both directions by the oracle-sanity harness: gold solution passes, untouched setup fails (ADR-0017 §5). |
| **Regression Probe** | One harness-behavior check: fixture + prompt + metrics asserting HOW decode works (right tool, minimal diff, gate respected), run host-native (`none` mode) on a temp dir. | Probes score behavior, Benchmark Tasks score outcomes (ADR-0017 §2,6). |
| **Judge** | A G-Eval LLM metric (`GEval(task_introduction, evaluation_criteria, model=<LiteLLM string>)`) built by the judge factory, which routes decode's provider to a LiteLLM id; `EVAL_JUDGE_MODEL` overrides. | Used only where a code metric can't decide (quality, groundedness, minimal-diff) — ADR-0017 §7. |
| **Experiment** | One Opik `evaluate()` run over a dataset: per-item scores + experiment-level aggregates, tagged with `experiment_config` (agent model, git sha). | Baseline comparisons fetch prior Experiments by name (ADR-0017 §6,8). |
| **Trial** | One of `k` repeated runs of the same dataset item (`evaluate(trial_count=k)`, `--trials k`). | The unit under pass@k / pass^k (ADR-0017 §8). |
| **pass@k / pass^k** | Suite aggregates over k Trials: pass@k = at least one trial passed; pass^k = every trial passed (the reliability bar). pass@1 is the k=1 mean. | Computed by `experiment_scoring_functions`, with the flakiness rate (0 < passes < k) and cost-normalized success-per-dollar (ADR-0017 §8). |
| **Threshold Gate** | The manual pre-merge ritual: `evals/regression/test_thresholds.py` asserting `aggregate_evaluation_scores()` ≥ a per-metric threshold table — outside `testpaths`, never in `make ci`. | Regression surface (a); surface (b) is the Opik Test Suite (ADR-0017 §6,9). |
| **Test Suite (Opik)** | The contrasting regression surface: natural-language assertions on a suite (`get_or_create_test_suite` → `run_tests` → `pass_rate`) over a subset of probes. | Deliberately kept beside — not instead of — code metrics: the contrast is the lesson (ADR-0017 §6). |
